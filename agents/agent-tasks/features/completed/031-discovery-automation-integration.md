# Automate Discovery Ingestion via Dashboard

**Status:** Completed  
**Type:** Feature

## Description

Currently, discovery data generated by the CLI requires manual import into the dashboard. To realize our vision of a seamless control plane, the dashboard must be able to trigger the `enterprise-multi-org-scan.yml` workflow and automatically ingest the resulting JSON bundles once the scan completes. This bridges the gap between CLI-driven discovery and dashboard visualization.

## Acceptance Criteria

- [x] A new or updated UI component exists in the Dashboard to trigger discovery scans.
- [x] The dashboard securely dispatches the discovery workflow using the local CLI server proxy (`/api/actions/workflows/:workflowId/dispatch`).
- [x] The dashboard polls or listens to the workflow run status.
- [x] Upon successful completion, the dashboard automatically downloads and unpacks the generated discovery artifact using the `/api/actions/artifacts/:artifactId/unpacked` endpoint.
- [x] The downloaded discovery data is hydrated into the dashboard's application state without requiring manual file uploads.

## Component(s) Affected

- `apps/dashboard` (UI, State Management)
- `apps/cli` (Local Server Proxy endpoints if additional CORS/handling is needed)

## Suggested Approach

1. Extend the existing `LiveConsoleTab` or create a new `DiscoveryTab`.
2. Add a form to configure discovery inputs (`enterprise_slug`, `modules`, `dry_run`).
3. On submit, send a POST request to the local CLI server's action proxy to trigger `enterprise-multi-org-scan.yml`.
4. Implement a polling mechanism against `/api/actions/runs/:runId` to monitor the run state.
5. When the run completes, fetch `/api/actions/runs/:runId/artifacts`, identify the `discovery-enterprise-*` or `discovery-org-*` artifact, and call the unpack endpoint.
6. Dispatch the unpacked JSON payloads to the dashboard's data store (e.g., React Context or Redux).
