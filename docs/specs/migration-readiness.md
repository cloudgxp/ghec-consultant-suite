# Migration readiness and advisory analysis

Status: rule specifications only. `packages/analysis` contains an interface and an empty registry; fixture findings are invented examples.

**MIG-EVID-001.** Rules are deterministic, pure and versioned. They operate only on validated evidence, declare needed modules/fields, and report unknown when prerequisites are missing, stale or incomplete. Findings include organization, entity/execution references, rule ID/version, confidence and caveats. AC: identical input yields identical output; no network, environment, clock or UI dependencies; missing evidence never improves a readiness conclusion.

**MIG-SCORE-001.** Use per-dimension states `review_required`, `no_issue_observed`, `unknown`, `not_applicable` in the eventual analysis model. These are analytical states, not current serialized schema properties. `no_issue_observed` is not “safe to migrate.” No global numeric score or hard blocker without an approved destination-specific rule. AC: all missing modules produce unknown; report states coverage denominator and never treats an unavailable collector as passed.

| Rule ID / dimension                    | Required evidence                                                                     | Proposed advisory and acceptance criteria                                                                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MIG-SIZE-001 / repository size         | Repository size with units, source and known coverage; destination-specific threshold | Above an approved threshold, advise migration rehearsal and size review. No hard-coded GitHub limit. Unknown size yields unknown.                                   |
| MIG-LFS-001 / LFS                      | LFS indicator, storage/object counts and completeness                                 | Detected LFS with unknown totals prompts approved measurement and transfer planning, never guessed storage. Fixture exercises this case.                            |
| MIG-ACTIONS-001 / automation           | Workflow counts/names, runner types and enabled state                                 | Self-hosted runners prompt runner/network/dependency review; metadata cannot prove workflow portability. Missing runner data yields unknown.                        |
| MIG-CONFIG-001 / secrets and variables | Approved metadata names, scope and timestamps                                         | Advise customer-managed recreation and validation of configuration references; never propose extracting values. A listed secret does not prove use by any workflow. |
| MIG-POLICY-001 / policies              | Branch protection/ruleset metadata and enforcement                                    | Compare only with verified destination capability; flag manual policy mapping needs and gaps. No claim of equivalent enforcement from names alone.                  |
| MIG-ACCESS-001 / teams and access      | Team hierarchy, membership coverage, repository mappings                              | Advise identity/team mapping and least-privilege review; unknown membership remains a visibility gap. No cross-org merging by display name.                         |
| MIG-INTEGRATION-001 / integrations     | App/webhook/deploy-key/signing metadata                                               | Recommend owner-led reauthorization, endpoint and key lifecycle planning; keys and destinations are not exported. Presence alone is not evidence of active use.     |
| MIG-ASSET-001 / packages and releases  | Types, inventory, size/coverage and registry context                                  | Ask for registry/package/asset transfer plan and verified destination support. Missing asset bytes never become zero.                                               |
| MIG-IDENTITY-001 / identity and SSO    | Membership posture, outside collaborator and available SSO linkage                    | Advise customer identity/SSO mapping review; do not infer enforcement or authentication success from a link. Unavailable SSO data yields unknown.                   |
| MIG-SECURITY-001 / security tools      | Accessible settings and alert metadata, collection completeness                       | Advise configuration/license and history-retention review; inaccessible alerts cannot imply no vulnerabilities.                                                     |

**MIG-TARGET-001.** Stakeholders must specify source/destination products, identity model, acceptable downtime, evidence freshness, repository/asset size thresholds and risk severity mapping before these rules become release conclusions. AC: rules with target-specific claims cite approved configuration and verified source documentation; universal “migration ready” certification is absent.

**MIG-EXPLAIN-001.** Findings must separate observed facts from derived risk and suggested next action. Avoid overstating certainty or counting the same evidence twice. AC: a report can display a rule's evidence and limitations, and aggregation respects organization scope and unknown denominators.
