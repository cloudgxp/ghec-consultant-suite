# Curated GitHub Platform & Migration Documentation Reference

This directory contains a focused, curated local snapshot of official GitHub documentation vendored directly from [`github/docs`](https://github.com/github/docs), with autogenerated REST and GraphQL reference stubs hydrated directly from GitHub's GHEC OpenAPI (`src/rest/data/ghec-2022-11-28`) and GraphQL (`src/graphql/data/ghec`) schema definitions.

---

## 1. Purpose

The purpose of this documentation set is to provide coding agents (Antigravity, Codex, etc.) and human maintainers with an authoritative, offline, locally searchable reference across all **32 GHEC-to-GHEC-EMU migration modules** and **discovery/sizing engines**:
- GitHub Enterprise Importer (GEI) mechanics, limitations, and caveats.
- GitHub Enterprise Cloud (GHEC) and Enterprise Managed Users (EMU) identity, SCIM, SAML, and permissions models.
- Hydrated GitHub REST (`2022-11-28`) and GraphQL API endpoints, mutations, input objects, schemas, and pagination patterns.
- Authentication mechanisms (GitHub Apps, Installation Tokens, Fine-Grained & Classic PATs, SSH & Deploy Keys, SAML SSO).
- Organization and repository governance (Custom Roles, Organization Roles, Security Managers, Rulesets, Branch Protections, Webhooks, Environments, Actions Variables, Secrets, Custom Properties, Autolinks, IP Allow Lists).
- Collaborative & Registry resources (Projects V2, Discussions, Packages, Issues, Pull Requests, Releases, Git LFS, GHAS Code/Secret Scanning & Dependabot).

Having these docs and hydrated API schemas vendored directly inside the workspace eliminates hallucinated API endpoints, empty autogenerated markdown stubs, outdated schema assumptions, and ungrounded guesses regarding EMU and migration constraints.

---

## 2. Upstream Source & Snapshot Identity

- **Source Repository:** `https://github.com/github/docs`
- **Default Tracking Branch:** `main`
- **Current Snapshot Metadata:** Recorded in [`VERSION`](VERSION)

Each synchronization resolves `main` (or a specified `--ref`) to an exact, single commit SHA before copying any files and hydrating API reference pages. The local files strictly represent that immutable upstream state.

## 4. Intentionally Excluded Areas

To maintain a compact (~8.9 MB), high-signal reference corpus, non-essential documentation and binary assets are omitted:
- Multi-hundred-MB image/video assets (`assets/`) and non-English translations.
- Raw multi-version OpenAPI JSON dumps for GHES/FPT (`src/rest/data/ghes-*`, `src/rest/data/fpt-*`).
- GitHub Education, Sponsors, Desktop, Mobile, Copilot consumer tutorials, and Pages hosting guides.
- General Git beginner tutorials and Marketplace billing guides.

## 5. Agent Usage Protocol

When developing or modifying discovery, migration, API adapters, or CLI commands:

1. **Consult Authoritative Documentation First:** Before making assumptions about endpoint payloads, parameter names, required scopes, rate limit response headers, or EMU behavior, search and read the corresponding document under `references/github-docs/`.
2. **Follow Liquid Reusables When Referenced:** When a markdown article includes `{% data reusables.<domain>.<snippet> %}`, read the corresponding file at `references/github-docs/data/reusables/<domain>/<snippet>.md`.
3. **Do Not Hallucinate Endpoints:** If an endpoint or feature is not documented in `references/github-docs/` or verified in Octokit types, verify against the live API or open an explicit question in `docs/architecture/decisions.md`.
4. **Record Consulted Documentation:** In task completion notes and PR summaries, cite the local documentation files consulted (e.g. `references/github-docs/content/rest/orgs/organization-roles.md`).

## 6. Authority & Validation

The vendored documentation represents GitHub's documented platform contract. However:
- If a discrepancy arises between documentation and `@octokit/rest` / `@octokit/graphql` TypeScript types, Octokit types and actual HTTP responses take precedence.
- All code changes must still be verified with unit tests, schemas, and live or mock integration tests.

## 7. Synchronization & Maintenance

To update the local documentation snapshot to the latest `github/docs@main`:

```bash
# Using npm script:
npm run docs:sync

# Or invoking directly:
node scripts/sync-github-docs.mjs

# Or synchronizing against a specific branch, tag, or commit SHA:
node scripts/sync-github-docs.mjs --ref <commit-or-tag>

# Dry run mode (validates allowlist without writing changes):
node scripts/sync-github-docs.mjs --dry-run
```

The sync script automatically:
1. Performs a sparse, blobless shallow clone of `github/docs` in a temporary directory (`/tmp/github-docs-import-...`).
2. Resolves the exact commit SHA.
3. Enforces that all allowlisted paths exist upstream (failing non-zero if upstream reorganizes or removes paths).
4. Cleans up previously synchronized files to eliminate stale entries.
5. Copies all allowlisted `content/` and `data/` files and hydrates autogenerated `content/rest/` and `content/graphql/reference/` stubs from upstream GHEC schema definitions.
6. Updates `VERSION` and refreshes `LICENSES/`.
7. Cleans up temporary checkout directories.
